# 2026-08-05 工作日志

## LocalDataApi 后端代码审查 + DDD 重构(完成)

### 任务
对 .NET 10 项目 LocalDataApi(对接遗留 ERP 中文表 + 企业微信 SDK)完成:审查 → 优化建议 → DDD 分层重构,保持前端接口契约零影响。

### 审查主要发现
- 无分层、上帝类(PMCService 2804 行 / WeChatWorkService 1507 行 / PMCController 946 行)
- 实体即 DTO、AutoMapper 引而未用、大部分接口无鉴权、自定义 Token 无过期校验
- 循环内逐条 SaveChanges、裸 HttpClient 取 jsapi_ticket、生产暴露 Swagger、大量注释死代码

### 重构结果(单项目内模块化分层)
- 新结构:`Api/`(9 控制器 + 中间件)、`Application/`(5 域 15 用例 + Common)、`Domain/`(Blf/Erp/Identity/Ppc/WeChatWork 实体 + IRepository/IUnitOfWork)、`Infrastructure/`(AppDbContext + Migrations + TokenProvider)
- PMCService → 6 个应用服务(PmcProduct/DeliveryReview/Scheduling/Bom/WorkOrder/ExternalProduction);WeChatWorkService → 5 个服务(Organization/Message/SmartSheet/GroupChat/JsSdk)
- PMCController → 6 个控制器,显式 `[Route("api/PMC")]` 保持路由;36 个端点逐一核对一致
- 修复:BLF 删除合并 SaveChanges、TokenProvider 走 IHttpClientFactory、企业微信用户服务接入 Token 缓存、Swagger 仅开发环境、清理死代码/冗余 using
- 说明:Bom 服务含分析单号生成(SaveSchedulingAnalysisAsync 系列),因排产分析服务反向依赖 GetBomByItemNo,合置避免循环依赖
