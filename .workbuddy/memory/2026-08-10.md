## RBAC 发布前优化收尾 + 修复预存令牌校验阻断 Bug（09:42~09:58）
继续前序《YCData_RBAC生产发布重要整改计划》的发布前验证，确认 P0-1（默认管理员初始化）与 P1-7（首次登录强制改密/密码强度）已全部落地并端到端验证通过。

### 验证发现并修复的预存生产阻断 Bug（关键）
- **现象**：`change-password`/`update-profile`/企微免登等一切携带令牌的接口均返回 401「未登录或登录已失效」，登录本身正常。
- **根因**：`AuthController._tokenSecret` 与 `CurrentUserService._tokenSecret` 取值用 `configuration["Auth:Secret"] ?? 回退值`。
  `Auth:Secret` 配置为空串时 `??` **不回退**（空串非 null）→ 校验端用空串，而 `UserService.LoginAsync` 用 `IsNullOrWhiteSpace` 回退到开发密钥签名 → 签名不一致 → 令牌全部校验失败。
- **修复**：`AuthController.cs:26` 与 `CurrentUserService.cs:18` 统一改为 `string.IsNullOrWhiteSpace(secret) ? 回退值 : secret`，与 `UserService` 一致。
- **排查要点**：`Proxy-Connection` 响应头是干扰项——直连 127.0.0.1 同样 401，纯属密钥取值缺陷，与代理无关。令牌经 base64 解码+HMAC 复算确认 dev 密钥签名，锁定为校验端密钥缺失。

## 2026-08-10 午间：修复 admin 解绑 VIEWER 后登录 409

### 现象
用户在管理后台把 admin 的 VIEWER 角色去掉后，前端登录接口返回 500/409：
`{"success":false,"message":"数据已被其他请求创建或修改,请刷新后重试。"}`。

### 根因
`UserService.LoginAsync` 登录成功后会调用 `UserRoleService.EnsureUserHasRoleAsync(userId, _defaultLoginRole)`，其中 `_defaultLoginRole` 默认值为 `VIEWER`。
该方法原先只检查 `UserRoles` 中 `IsActive=true` 的记录；当用户在后台解绑 VIEWER 后，数据库里仍保留一条 `(admin, VIEWER, IsActive=0)` 的软删除记录，`EnsureUserHasRoleAsync` 误判为不存在，直接 `Add` 新记录，违反 `(UserId, RoleId)` 唯一索引 → SQL 2601/2627 → GlobalExceptionMiddleware 返回 409。

### 修复
`Application/Identity/UserRoleService.cs` 的 `EnsureUserHasRoleAsync` 改为：
1. 查询所有（含已撤销）`UserRole` 记录；
2. 若已存在且 `IsActive=true` → 直接返回；
3. 若存在但已撤销 → 复用记录，置 `IsActive=true`、清空 `RevokedAt`、更新 `AssignedAt`；
4. 仅当确实不存在时才 `Add` 新记录。

### 验证
- 修复前：admin 解绑 VIEWER → 登录 409 ✅ 复现
- 修复后：重新解绑 VIEWER → 登录 200，`Roles: ['ADMIN','VIEWER']`，数据库中 VIEWER 被重新激活 ✅
- 部署：停池 → publish → md5 比对/手动覆盖 DLL → 启池
