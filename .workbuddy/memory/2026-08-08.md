## 企微登录反复 400「redirectUri 不在可信域名白名单内」最终根因（10:24）
- **现象**：curl 直接请求返回 200，浏览器/axios 请求返回 400；截图显示 Params 中 redirectUri 为已编码字符串 `http%3A%2F%2F...`。
- **根因**：前端把已 URL 编码的 redirectUri 又作为 axios params 值传入，axios 再次编码，导致后端收到**双重编码**的 redirectUri（如 `http%253A%252F%252F...`）。后端 `Uri.TryCreate` 无法解析，白名单校验失败。
- **修复**：`WechatController.GetAuthorizeUrl` 增加 `NormalizeRedirectUri` 方法，将原始 URL / 单次编码 / 双重编码统一还原为原始 URL，再校验白名单、再生成企微授权链接（`GenerateAuthorizeUrl` 内部只做一次 UrlEncode）。
- **验证**：停止 IIS 站点+应用池 → `dotnet publish -c Release -o D:\IISWebSitefiles` → 启动后 curl 测试三种情况均返回 200，且生成的 `redirect_uri` 均为正确的一次编码 `http%3a%2f%2fwww.ycdcf.com%3a1001%2f%23%2fwechat-login`。
- **web.config**：`stdoutLogEnabled="true"` 已打开，方便后续看后端日志。
- **结论**：问题不在配置未加载，而在前端传参方式；后端已做防御性兼容，建议前端后续改传原始 URL（`location.href`），让 axios 自动编码。
- **结论**：前端/后端/企微三端已对齐，IIS 旧 dll 功能代码完整 → **应能跑通，待用户实测**。若仍失败，需重新 publish 最新代码（含 [REQ] 日志）到 D:\IISWebSitefiles 再定位。
